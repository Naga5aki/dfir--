# 通用取证解题框架（2026-10-31）

## 1. 边界声明

这套框架的目标是**把“任何案件”拆成可路由、可验证、可停止的工程流程**，不是承诺任何题都答对。模型能力、证据是否完整、工具授权、加密强度都会影响结果。可保证的是：

- 不把题面/题号写死在核心里；
- 先分类再选 profile/技能/预算；
- 每题独立进程、独立 pending；
- 证据缺失或工具失败时留下可恢复证据，而不是编造答案；
- 用 mock 基准和真实案件回归持续改结构，而不是靠一次成功下结论。

当前 2025fic 的 `dfir-solve.ps1` 仍是已验证的手机题专用入口；本目录的 `dfir_general.py` 是通用入口，二者暂不互相替换。

## 2. 结构

```text
题面文本
  │
  ▼
dfir_plan.py            题型/证据域分类 → profile / skills / budget / tool policy
  │
  ▼
dfir_general.py         案件 bootstrap → 每题子进程 → 硬墙/重试 → pending 判定
  │
  ├─ dfir-myos / dfir-max   手机 / 已有 MYOS 结果的电脑
  ├─ dfir                    PC / 通用
  ├─ dfir-re                 逆向
  ├─ dfir-pcap               网络
  └─ dfir-mem                内存
  │
  ▼
notes/pending-<q>.md    答案 / 证据 / 已排除 / 下一轮
notes/lessons.md        案件级教训（人工评审后再提升）
```

| 文件 | 作用 |

| `hermes\bin\dfir_general.py` | 通用 runner：逐题子进程、硬墙、重试、fallback pending、MockAgent |

| `benchmarks\mock\run_e2e.py` | MockAgent 端到端 runner 基准（6 项） |
| `reports\通用框架与Mock基准-2026-10-31.md` | 基准结果与限制 |

## 4. 路由规则

### 4.1 证据域

| 域 | 典型关键词 | 基础 profile | 深度 profile | 默认技能 |
|---|---|---|---|---|
| mobile | 手机、Android、APK、微信、聊天记录、便签、联系人、IMEI、UIN | dfir-myos | dfir-max | android-app-forensics, mobile-ctf-pipeline |
| computer | 计算机取证、电脑、检材三、E01、openKylin、磁盘镜像、Linux/Windows 镜像 | dfir-myos | dfir-max | myos-results-analysis, linux-loader, windows-loader, digital-forensics |
| pc | PC、Windows、注册表、NTUSER、Prefetch、EVTX、LNK、回收站、文件系统 | dfir | dfir-max | windows-loader, digital-forensics |
| network | pcap、流量、抓包、DNS、HTTP、IP、端口、URL | dfir-pcap | dfir-pcap | wire-toutetu |
| memory | 内存镜像、内存取证、Volatility、进程内存 | dfir-mem | dfir-mem | memory-forensics-local |
| reverse | 逆向、反编译、jadx、IDA、SO、二进制、加密算法 | dfir-re；手机上下文用 dfir-max | 同左 | 手机上下文用手机技能；否则 ida-reverse, android-malware-analysis |
| linux | Linux、ext4、xfs、syslog、bash_history、systemd、SSH | dfir | dfir-max | linux-loader |
| mac | macOS、APFS、HFS、plist、Keychain、iMessage | dfir | dfir-max | digital-forensics |
| cloud | 云取证、S3、OSS、Azure、M365、Workspace | dfir | dfir-max | digital-forensics |
| email | EML、PST、MSG、SMTP、IMAP、MIME | dfir | dfir-max | digital-forensics |
| database | MySQL、Postgres、MongoDB、SQLite、Oracle | dfir | dfir-max | digital-forensics |
| generic | 无法判断 | dfir | dfir-max | digital-forensics |

### 4.2 任务与预算

任务类型：`credential`、`reverse`、`timeline`、`date`、`count`、`media`、`network`、`locate`、`unknown`。

复杂度分数（可在 `dfir_plan.py` 调整）：

- 凭证 +3；逆向 +4；日期/时间线/媒体/网络 +2；数量 +1；未知 +3；
- 逆向域 +2；内存/网络/PC +1；
- 手机上下文下的凭证/日期/时间线/媒体 +1；
- 加密密钥/解密/跨检材/多源/证明/所有/全部 +2；
- 注册表/时间线/内存镜像/文件系统/多层/嵌套 +1。

分档：

- `base`：12 次工具迭代 / 480 秒；
- `complex`：16 / 600；
- `deep`：18 / 660；
- `retry`：6 / 240（仅普通失败且 pending 有具体下一轮）。

## 5. 案件配置（不写死题号/路径）

案件可在 `notes/case-profile.json` 覆盖路由：

```json
{
  "domain": "mobile",
  "profile": "dfir-myos",
  "deep_profile": "dfir-max",
  "skills": ["android-app-forensics", "mobile-ctf-pipeline"],
  "budgets": {
    "base": {"turns": 12, "seconds": 480},
    "complex": {"turns": 16, "seconds": 600},
    "deep": {"turns": 18, "seconds": 660}
  },
  "complex_questions": [2, 3, 4, 5],
  "deep_questions": [8],
  "tools": {"myos_first": true, "evidence_pack": true}
}
```

兼容旧的 `complex-questions.txt` / `deep-questions.txt`。优先级：显式 sidecar/案件配置 > 自动分类 > 默认值。

案件特定提示放 `notes/case-hints.md`；不要写进通用技能。通用技能只放跨案件规则。

## 6. 运行

预览计划（不启动模型、不写证据）：

```powershell
python D:\ForensicsAgent\hermes\bin\dfir_general.py `
  --case-root D:\forensics\cases `
  --questions "1-8" `
  --questions-file D:\forensics\cases\notes\questions-1-8.txt `
  --dry-run
```

通用 runner 默认会尝试刷新 MYOS 紧凑索引（`--skip-myos` 可跳过）；`--mount` 是显式 opt-in，会先 mount + appmap。已有成功 pending 的题默认跳过；未完成 pending 会归档到 `notes\prev\` 后重跑。

实际运行（通用 runner；先小批再全批）：

```powershell
python D:\ForensicsAgent\hermes\bin\dfir_general.py `
  --case-root D:\forensics\cases `
  --questions "3-5,8" `
  --questions-file D:\forensics\cases\notes\questions-1-8.txt `
  --batch-budget 2400
```

单独预览一道题：

```powershell
python D:\ForensicsAgent\hermes\bin\dfir_plan.py `
  --q 1 --question "请从检材中确定设备名称" `
  --notes D:\forensics\cases\notes --json
```

## 7. Mock 基准

```powershell
python D:\ForensicsAgent\benchmarks\mock\run_mock.py
python D:\ForensicsAgent\benchmarks\mock\run_e2e.py
```

基准不调用模型、不读真实案件。它验证：

- 26 道合成题的 domain/task/profile/tier 路由；
- 成功/UNKNOWN/EXHAUSTED/NO_ANSWER 的 pending 判定；
- 多题集按题号范围选择；
- complex/deep sidecar 覆盖；
- 计划中的 profile 配置文件存在且为 local provider，技能存在；
- MockAgent 端到端：OK、TOOL_BLOCKED、重试成功、EXHAUSTED、BUDGET_EXHAUSTED、TIMEOUT 及 fallback pending。

## 8. 学习闭环

1. 真实案件运行后，用 `dfir_lesson.py` 写 `notes/lessons.md`：
   - 只写通用教训/证据位置/下一步；
   - 不写答案值、密码、token、密钥。
2. 同一教训至少第二个案件复现，才考虑提升：
   - 通用决策规则 → 对应 profile 的 `SKILL.md`；
   - 稳定路由规则 → `dfir_plan.py`；
   - 案件具体提示 → 该案件 `notes/case-hints.md`。
3. 不把单案例答案写进全局 memory；dfir profile 的 memory 当前关闭。
4. 每次改规则后跑 `run_mock.py` + `run_e2e.py`，再跑小批真实题；退化就回滚。

示例：

```powershell
python D:\ForensicsAgent\hermes\bin\dfir_lesson.py `
  --notes D:\forensics\cases\notes `
  --category evidence-pattern `
  --lesson "某类 App 的正文不在主表，先枚举全部表再 grep" `
  --evidence "notes/case-hints.md" `
  --next "在 SKILL.md 增加通用表枚举规则"
```

## 9. 真实案件的验收指标

不要用“模型说它确定”验收。每个案件记录：

- 路由是否正确（domain/task/profile）；
- 正确且有原始字段支撑的题数；
- 平均/最坏耗时、重试次数、打满预算次数；
- `TOOL_BLOCKED`、`NO_QUESTION`、`BUDGET_EXHAUSTED`、`TIMEOUT`；
- pending 是否含答案/证据/已排除/具体下一轮；
- 是否读取了 findings/gold（必须为 0）；
- 同类题在第二个案件是否复现。

门槛应按题型分别设定；没有当前案件 gold 时只能人工核对，不能套用旧题集 gold。

## 10. 当前限制

- 通用 runner 只用 MockAgent 做了端到端测试，尚未用真实模型跑完整跨域案件。
- 内存和流量已有专门技能，路由直接选用，不再依赖一份通用仿真技能。
- 真实题的正确率需要多案件 gold，当前 26 道 mock 只验证框架决策，不验证模型能力。
- 旧 `dfir-solve.ps1` 与通用 runner 是并存关系；2025fic 手机流程仍以已回归的 PowerShell 入口为准。

## 11. hexp 导入后的入口

第 4 节的默认技能与 `dfir_plan.py` 的 `DEFAULT_SKILLS` 一致。电脑、计算机、检材三先于账单；微信、检材二、手机取证先于账单。

| 题面 | profile | 技能 |
|---|---|---|
| 已有 MYOS 结果的电脑题 | `dfir-myos` | `myos-results-analysis` |
| 已有 MYOS 结果的手机题 | `dfir-myos` | `android-app-forensics`, `mobile-ctf-pipeline` |
| 内存镜像 | `dfir-mem` | `memory-forensics-local` |
| 已有 pcap | `dfir-pcap` | `wire-toutetu` |
| 银行流水、账单 | `dfir-pcap` | `bill-flow-analysis` |
| EXE / APK 逆向 | `dfir-re` | `ida-reverse`、`android-malware-analysis` |
| 用户明确要求笔录 | `dfir` | `forensic-record-draft` |

计算机已有 MYOS 结果时，第一跳是 `myos-results-analysis`：先读已有 `device_map.computer.summary.txt`，再补一条有界查询，不是重新取证。手机已有 MYOS 结果时，第一跳是 `android-app-forensics`：先读 `device_map.myos.summary.txt`，不要把电脑插件库用到手机题。
