# 正式 Memory 受控晋级与最小闭环修复轮（Memory Promotion & Hygiene）

适用：训练者下发「正式 Memory 受控晋级」或对晋级成果追加「最小闭环修复」指令（冻结/审计归档/定点替换/全量泄漏扫描/候选元数据修正/增强验证器+探针）。全流程已实证：晋级轮 58 候选 / 验证器 19 项 / 探针 11 类；修复轮 21 项验证器 / 13 类探针 / 候选 58-58 一致 / 泄漏未授权 0。产物根 `work/<项目>/memory-promotion-v5/`，修复轮落 `memory-promotion-v5/hygiene-fix/`（scripts/、audit-archive/、post-fix-reference/、freeze-*.{sha256,json}）。

## 1. 晋级轮骨架
1. 门禁（只读）：源哈希/Lock、既有清单现场复算、授权目录核对；FAIL 即零修改停止。
2. 候选清单**从证据重新生成**（不照抄旧汇总）：知识卡 + claim 状态列现场统计 + 实验目录现场核对（计划未执行 ⇒ 降 Source-Only，不标 Verified）。处分七类：New Playbook / Merge Existing / Extend Existing / Knowledge Map Only / Source-Only Reference / Tool-Gap Record / Reject；Pending 与 Active Conflicts 数一致。
3. 泄漏+冲突审计（对 staging 副本跑）：CURATED 白名单逐条理由；策略性声明行（文件头明示不收某类值）不判泄漏。
4. 备份 5 文件（大小+SHA-256清单）→ staging 候选构建 → 原子替换 → 磁盘回读逐字节 → 回滚记录；再演一次「回滚→重建→重应用」验证回滚路径可用。
5. **新会话部署冒烟**：`delegate_task` 起全新会话，只允许读正式 Memory 文件答 N 题；每题须给文件+定位符；未收录必须如实回「未收录（cannot verify from memory）」，禁先验知识补答；设 2 道对照题验诚实性。产出 `deploy-smoke.json`：retrieval_success_rate / rule_hit_rate / errors_extended / unverified_range_false_positives / controls。
6. 增强验证器（示例 19 项）+ 失败探针（示例 11 类），探针全部在系统临时沙箱执行、正式树零写入。
7. 报告 + `report-hash.txt` sidecar + `round-final-hashes.json`（含报告与 sidecar；验证器运行产物排除，见 §9）。
8. 终态字符串 + 停等审核；Pack C/闭卷类结论只写「训练者豁免」，禁写 Passed。

## 2. 修复轮骨架（脚本序列 h01..h06）
- **h01 冻结**：活跃 Memory 全文件 + 证据全树（排除 hygiene-fix 自身）→ `freeze-pre-fix.sha256`（`sha|size|kind|path`）+ json 摘要；此后所有变更可逐条对照。
- **h02 审计归档**：含真实答案值的历史文件副本 → `audit-archive/`（`attrib +R` 只读），并登记该值全部历史存在点（报告/证据副本/归档目录；只读侦察，不修改）；活跃文件仅替换值本身，错误原因/经验/结论保留。
- **h03 候选元数据修正 + 程序化核对**：修正表按「归档(pre-fix) vs 现盘(post-fix)」字段差分生成（幂等）；核对 N/N 通过。
- **h04 全量泄漏扫描**（§4）。
- **h05 更新索引/报告补记/sidecar/最终清单/磁盘回读记录**（§9 清单口径）。
- **h06 增强验证器（含新增硬检查）+ 探针重跑**（§6-§8）。

## 3. 定点替换纪律
- 精确匹配整个值（注意反引号包裹），断言恰 1 次命中；替换后全文断言：无非空 `flag\{...\}`、答案令牌与全部变体 0 命中。
- 前后对照入 `targeted-fix-record.json`：before/after 行、size、SHA-256、保留说明；并生成 `post-fix-reference/` 参考副本供验证器做新基线。

## 4. 全量泄漏扫描设计（非增量）
- 范围=全部活跃 Memory 文件（含只读参考件），逐行全文；变体矩阵：原文 / 令牌 / base64 / hex / 反转 / 大小写。
- **只存哈希签名**：扫描器与证据文件不落敏感明文；行内候选抽取（`[A-Za-z0-9+/=_.\-]{12,}`、`[A-Z][A-Z0-9_]{7,}`、整行）+ base64/hex 解码后再比对 sha256 签名集合。
- 分类放行表（逐条登记理由）：术语命中（口令/密码=知识术语或工具名）、路径斜杠串与术语、工具二进制 SHA-256（授权工具事实）、既有登记（去重键/参考件示例）、题目编号（训练日志上下文，保留错误原因所需）。
- 每文件设**十六进制命中预算**（如工具哈希 3 / 去重键 1 / 参考件示例 4），超预算即 FAIL——新注入哈希必被捕获。
- 硬指标：未授权=0；历史答案值及全部变体=0；修复后追加「归档占位符存在」断言。

## 5. 候选处分↔目标语义表（验证器现场复算 N/N）
| 处分 | 目标要求 | 核验 |
|---|---|---|
| New Playbook | 目标文件含 playbooks；定位符=新建 P 编号（须在新增区） | P 标题存在 + 关键词命中 + 全部 New 目标恰为新增区全集 |
| Merge Existing | 定位符=既有/本轮已建立 P | 该 P 存在且含并入关键词 |
| Extend Existing | 定位符=既有 P | 含「晋级轮补充」标记 + 关键词 |
| Knowledge Map Only / Source-Only / Tool-Gap | 目标=总结文件 + §N | § 存在 + 关键词命中（SO 条目须有 SO 标注） |
| Reject | **目标=[]（空）** | 理由保留且含 Reject；禁登记任何写入目标 |
- 每条候选附结构化「目标定位」`{文件, 定位符, 核验关键词}`；落点其实不存在的条目（如样本特定背景未独立落盘）按真实落点改写目标与关系文本，**不新增正文凑一致**。

## 6. 授权变更账目化（新一轮合法改动旧冻结基线时）
不削弱检查、只改期望，三件套：
1. 比对基线 override：被授权文件用「修复后参考副本」做逐字节基线，其余文件仍与旧 staging 比；
2. 旧基线不可变断言：override 文件在旧 staging 中必须仍等于上一轮记录值（staging 被改 ⇒ FAIL）——老探针继续只打自己的检查；
3. 「官方==记录」检查改写为：官方==最新清单 **且** 与上一轮 apply-record 的差异集合==授权集合（逐文件枚举断言）。

## 7. 两个可复用新增硬检查
- **全量活跃 Memory 扫描（非增量）**：按 §4 实现 + 占位符存在断言。
- **处分/目标语义一致 N 条现场复算**：按 §5 遍历候选 JSON，现场解析 playbooks 的 P 节与总结的 §N 节做关键词命中；Reject 必须空目标；New 目标全集校验。

## 8. 新增检查的定向探针（检查间隔离）
- **编码变体注入探针**：从只读审计归档现场提取历史值并编码（hex），注入**非 FILES 的参考文件** ⇒ 只命中全量扫描检查（增量泄漏扫描/逐字节检查保持安静）。
- **处分篡改探针**：沙箱候选 JSON 中把 Reject 目标改非空 ⇒ 只命中语义检查。
- 探针记录 failed_checks 列表；干净副本 rc=0（全部检查 pass 或 pending）是套件有效必要条件。

## 9. 工具工程陷阱（本类轮反复出现）
- **写盘后自算哈希先关句柄**：`json.dump(obj, open(p,"w"))` 缓冲未刷即 getsize/sha ⇒ 清单记旧值；症状=尺寸相同、哈希不同、清单一致性检查莫名 FAIL。一律 `with open(...)`；「同一路径先写后追加条目」按 normcase 去重。
- **沙箱路径审计**：新检查读文件须区分真实运行（读正式证据目录）与沙箱运行（读沙箱副本或 pending）；探针结果读取同理——否则「干净副本 rc=0」被上一轮结果卡死。
- **更新脚本幂等**：报告追加/索引行替换加「已应用」守卫（清单会在后续修复后重建、脚本重跑）；索引/报告改动属 §6 授权变更，逐一登记。
- **生成器式脚本改造**（复制旧验证器 + 字符串替换生成新脚本，与既有「JSON regex 双转义」同族）：替换针用 `chr(92)` 构造消歧；生成后 `py_compile` + 逐行审计反斜杠（文件层计数 vs 目标转义值）+ 与源文件逐行 diff 含反斜杠行；沙箱 build() 复制清单随新检查同步扩展（参考副本/新清单文件）。
- **清单排除集**：validator-result.json / probe-results.json / dryrun / 子进程输出目录 / 重跑即变的中间清单一律排除；最终清单一致性检查在**最后一次运行之后**复验一次（run 后 bad=[]）。

## 10. 交付形态与终态
- 交付消息五件套：定点修改前后对照（行号/大小/完整 SHA-256 before→after）、关键文件完整 SHA-256 表、全量泄漏扫描结果（分类计数 + 未授权=0）、候选元数据修正表、最终验证结果（验证器 N/N / 探针 N/N / 干净副本 rc=0 / 外部表面零修改）。
- 终态字符串按指令原文（示例形态 `Misc Memory Promotion Completed — Active Memory Hygiene Verified`）；同时更新索引行与报告补记 §，sidecar 与最终清单同步重建。
- 收尾声明：不开始新训练、不写全局 Memory/技能、不生成 Pack C、不删历史证据，等待下一阶段指令。
