# 图像结构/隐写分析可复用方法（SecurityLab Day 3，训练者样本验证 2026-08-26）

全部方法已在 8 个陌生样本上验证。纪律：先类型+结构+异常定位，再对已定位数据定向解码；任何结论需"原始字节/结构证据"+"第二种独立方法或可复现实验"交叉支持。

## PNG
- **chunk walk**：`\x89PNG\r\n\x1a\n` 后循环 `len(4B BE) + type(4B) + data + crc(4B BE)`；**CRC 重算** `zlib.crc32(type+data) & 0xffffffff`，存储值必须一致。
- **IHDR 尺寸修复**：IDAT 解压长度 ÷ 行距 = 真实行数。行距 = `1 + 3*宽`（RGB8）。选能**精确整除**的 (宽,高) 组合（例：58374 = 54×1081 = 54×(1+3×360) → 真实宽 360，IHDR 宽被改成 180）。修复：work 副本改 IHDR 宽/高（大端 @16-19/@20-23），**重算 CRC** 写回 @29-32。改完 `magick identify` 确认。
- **IEND 尾随数据**：chunk walk 记 IEND 结束偏移（=IEND 起点+12）；尾随长度 = 文件长 − 该偏移；切取 → `file`/zipfile 独立验证 → 读内容（不执行）。ExifTool 的 "Trailer data after PNG IEND chunk" 警告是独立佐证。

## JPEG
- **marker walker**：跳过填充 FF；`FF <marker> <seglen BE 2B>`；SOS 后是 entropy 数据（到下一个非 00/FF 的 FF marker）。区分：**COM/APPx = 可编辑元数据**（COM 段常含 base64/注释），DQT/DHT = 量化/霍夫曼表，SOF0 = 帧参数，SOS+entropy = 像素内容——先区分再解码。

## RGB-LSB 位流
提取必须明确四要素并写进报告：
1. 像素遍历：行主序（y→x）
2. 通道序：R,G,B 逐像素交织
3. 取位：每字节 LSB
4. 字节位序：MSB-first（每字节 bit7→bit0 组装）
- **前 16 位常为长度字段**（大端）；长度与消息必须精确相等（验证：`flag{`5+内容+`}`1 = 长度）。
- **双实现交叉验证**：cv2 与 PIL 各写一遍提取，结果必须一致。
- 反例排除：BGR/列主序/LSB-first 出非文本即排除证据。

## GIF
- **GCE 解析**：`21 F9 04 <flags> <delay LE 2B> <transparent> 00`，**delay 在 GCE 起点+4**（易错点：+6 是 transparent 字段）。帧延迟和（cs 合计）应与 ExifTool Duration 一致。
- **帧文字读取（免下载）**：Windows 内置 OCR（WinRT `Windows.Media.Ocr.OcrEngine`，PowerShell 脚本，UTF-8 BOM）；stylized 单字形 OCR 会失败 → 用像素级 ASCII 渲染补足（二值化 + 1px/字符 打印）。字形高度判大小写：x-height 字母 ~12px vs 大写 ~23px（同字体对比）。
- **LZW 尾随检测坑**：自写 GIF LZW 解码器极易在 code-size 增长语义上出错（固定 9 位解码器会假命中 END 码、错误增长会少解符号）。**可靠替代 = PIL 截断实验**：逐步截断 LZW 子块负载重建 GIF，PIL 恰好能解出全部像素的最小长度 ≈ 真实 END 位置；若需接近全长则无隐藏尾随。

## GIF Global Color Table 位平面（GCT stego）
- 先求调色板"干净公式"：逐通道对候选公式（R=i、G=5i mod 256、B=255-i 等）算偏差分布，偏差 ~±1 且大多数为 0 的那个就是干净公式。
- 载体 = 偏差/翻转：`value = formula XOR m`，m∈{0,1}；**奇偶决定 ±1 符号**（i 偶→+1、i 奇→−1）是 XOR-LSB 翻转的标志。
- 像素 index 公式可逐像素验证（例：index=(4x+3y) mod 256，4096 像素零异常 → 图像本身无载体）。
- 翻转位流 ~130 位，常见单通道/组合位/位序/反转方案解不出时如实报告"机制确认、编码未匹配"，不伪造。

## QR 修复
- 定位：二值化 → 黑像素 bbox = 内容区（余下是静区）→ 模块尺寸 = 内容边长/模块数（33 模块 = v4；25=v2...）→ 网格采样（模块中心）。
- 确认缺失 finder 的模块坐标（TL=0,0 / TR=0,26 / BL=26,0 for v4），8×8 区域全白 = 被擦除。
- 修复：work 副本覆写标准 7×7 finder（外环黑、白环、3×3 黑核）+ 分隔区（第 7 行/列）置白；**备份全部被覆写模块的原始值**。
- 验证：修复前解码器必须解不出（''），修复后多次（≥3）重复解码稳定一致。

## flag 大小写纪律（教师纠正）
组合多段解出的 flag 时**保留各段原始大小写**，不得自行规范为小写。例：培根/云影/仿射三段均解出大写 → `flag{BACON_SKY_AFFINE}`（不是 `flag{bacon_sky_affine}`）。Bacon 五元组按 A=0/B=1 位序读（`AAABA`=00010=2='c'），位序错会导致 "baeon" 类错误。

## 多图缺列重建与边缘列诊断（2026-09-27 增补；原题 + 3 个迁移变体验证）

- **触发**：两张同高图像（如 24 位 BMP + 一张缺列的 PNG），提示含"缺列/需加宽/widen"类线索。先做**逐列统计**（字节熵、非白像素比例、相邻列差）定位异常边缘列与供体列，再决定拼接方案。
- **重建**：以另一图的对应边缘列作供体补入缺口；合成输出按**列主序（先列后行）**序列化 RGB 字节流，并**截断到目标容器的块长倍数**（如 512）——供体位置与遍历顺序（列主序 vs 行主序）都要做**有限候选对照**，不要把"恰好一列/右起一列"当法则。
- **判定**：不以视觉观感判定；以**目标容器结构**收口（解密后魔数 + 头 CRC 双校验；错误供体可能只毁主头——主/备头与数据区须分别检验）。
- **BMP 解析要点**：24 位 BGR；行宽按 4 字节对齐（含行填充）；高度为正=自底向上、为负=自顶向下；尾随数据自声明像素末端之后开始。
- **PNG 解析要点**：过滤器需覆盖全部五种（含 Paeth）；IDAT 可多块、按序拼接；先验 chunk CRC 再解码；缺列不能靠改 IHDR 加宽变出（必须外部供体）。
- **失败表现 / 停止条件**：行主序输出双头校验全败、错列输出毁主头（备份头独立仍有效）——负控制实测；有限候选与少量排列均无结构命中即回其他线索；同一路线三次无新增结构证据即停。
