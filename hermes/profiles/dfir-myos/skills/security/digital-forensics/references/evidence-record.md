# 证据收口

下结论前按这八个字段记一条证据。缺 `receipt` 就不要写这条事实。

| 字段 | 含义 |
|---|---|
| source | 工具、表、文件或 MCP 短名 |
| object | 人、文件、设备、账号、IP、进程 |
| time | 检材时间与工具时间分开写 |
| action | 开关机、插入、发送、下载、登录、访问 |
| receipt | 当次回执位置，或查询语句加返回行 |
| grade | E1 / E2 / E3 / E4 |
| gap | 缺什么才能升级 |
| handoff | 缺口属于内存、流量、逆向或笔录时，写给哪个 profile |

## 等级

- `E1`：清单、权限、字符串、组件、静态声明。
- `E2`：可定位到源码、反编译、类、方法或调用链。
- `E3`：本次设备、版本、时间和交互范围内的运行回执。
- `E4`：至少一条 E2 加一条 E3 的交叉。单个插件不能直接生成 E4。

结论强度只用这些原词：已确认、高度支持、初步支持、线索提示、待验证。证据等级不等于结论强度。

解题提交值不得包含 E1、E2、E3、E4 或结论强度原词；没有 receipt 的句子写“未取到”。

## 措辞

- 静态发现只表示包内声明或代码线索。
- 本次观察到只覆盖当前设备、版本、时间和交互。
- 未观察到不等于不存在。不可见、未触发、未覆盖写“未取到”。
- 请求存在只证明通信。敏感字段出现才可称敏感字段传输。还要关联数据来源才能称本应用数据上传。
- 空结果、截断、任务未完成、TLS 未解密必须披露。
- 冲突证据并列保留，不擅自取舍。

## 本机来源

- APK 的 E1/E2 只来自已有 jadx 或 `android-malware-analysis` 回执。没有抓包或动态回执时，E3 写“未取到”。不要调用 thunder-app 技能。
- 内存的 E3 只来自 memforensics 或 lovelymem 的插件回执。
- 流量的 E3 只来自 wiremcp 或 `wire-toutetu` 的 `EVT-*`。
- MYOS 的 E3 只来自白名单工具的当次回执。
- 哈希必须逐字来自当次命令输出，不补位。
