# 通用取证框架与 Mock 基准（2026-10-31）

## 1. 本轮完成了什么

- 建立了案件无关的题型规划器 `hermes\bin\dfir_plan.py`：
  - 证据域：mobile / pc / network / memory / reverse / generic；
  - 任务：credential / reverse / timeline / date / count / media / network / locate / unknown；
  - 自动选择 profile、技能、基础/复杂/深度预算和重试预算；
  - 支持 `notes\case-profile.json` 与旧 `complex-questions.txt` / `deep-questions.txt` 覆盖；
  - 不把题号、案件路径、表名、答案写死在核心里。
- 建立了通用 runner `hermes\bin\dfir_general.py`：
  - 每题独立子进程；
  - 外部硬墙（预算 +60 秒）；
  - pending 判定、普通失败重试、工具阻塞/预算耗尽/超时/已排除停止；
  - fallback pending；
  - 默认刷新 MYOS 紧凑索引，`--skip-myos` 可跳过；`--mount` 才执行 mount + appmap；
  - 已有成功 pending 默认跳过，未完成 pending 归档到 `notes\prev\` 后重跑；
  - MockAgent 可做无模型端到端测试。
- 建立了案件级经验记录 `hermes\bin\dfir_lesson.py`，只写 `notes\lessons.md`，不自动改全局 memory/skill。
- 建立了 26 道合成题的 mock 基准和 6 条端到端场景。

## 2. 路由基准

`benchmarks\mock\run_mock.py` 结果：

| 检查 | 结果 |
|---|---:|
| 26 道题的 domain/task/profile/tier | 26/26 |
| pending 成功/UNKNOWN/EXHAUSTED/NO_ANSWER | 4/4 |
| 多题集范围选择 + sidecar/case-profile 覆盖 | 3/3 |
| 计划 profile 为 local provider 且技能存在 | 26/26 |
| 合计 | 59/59 |

覆盖的域：

- mobile：base / complex / deep，dfir-myos / dfir-max；
- pc：base / complex，dfir；
- network：complex，dfir-pcap；
- memory：base / deep，dfir-mem；
- reverse：deep，dfir-max（手机上下文）和 dfir-re；
- generic：base / complex / deep，dfir / dfir-max；
- linux / mac / cloud / email / database：基础/复杂路由到 dfir，技能为 linux-loader/utm 或 utm。

`dfir_plan.py --self-test`：8/8。

## 3. Mock 端到端

`benchmarks\mock\run_e2e.py` 使用 MockAgent，不调用模型、不读真实证据：

| 场景 | 结果 |
|---|---|
| 正常成功 | OK attempt=1 |
| 工具未授权 | TOOL_BLOCKED attempt=1 + fallback pending |
| 第一次 UNKNOWN 有下一轮、第二次成功 | OK attempt=2 |
| 有排除且无下一轮 | EXHAUSTED attempt=1，不重试 |
| `max_iterations` 且无下一轮 | BUDGET_EXHAUSTED attempt=1 |
| 超时 | TIMEOUT attempt=1 |
| 合计 | 6/6 |

## 6. 重要限制

- **没有真实模型跨域跑过**：通用 runner 只做了 MockAgent 端到端；真实能力仍需用案件验证。
- mock 基准验证的是框架决策，不是模型正确率。
- dfir-pcap / dfir-mem 目前只有 `utm-forensic-cli` 通用技能，缺专门的 PCAP/内存深度技能；需要在真实案件中沉淀。
- 题型关键词分类仍是启发式；长尾题会落到 generic，需要第二个案件复现后再调整规则。
- 旧 `dfir-solve.ps1` 是 2025fic 手机题的已验证入口；通用 runner 是新增入口，不应当作“任何题都已解决”。
- 不保证任何题都优秀；只保证路由、预算、停止和收口可测、可回归。

## 7. 下一步

1. 选 2–3 个真实跨域案件（至少手机 + PC，最好再加 PCAP 或内存）作为 benchmark，gold 放案件目录外。
2. 每个案件先 `dfir_general.py --dry-run` 看路由，再小批跑。
3. 真实失败后用 `dfir_lesson.py` 记 case-local 教训；第二案件复现后再改 skill/planner。
4. 每次改规则跑 `run_mock.py`、`run_e2e.py`，再加真实小批；退化回滚。
