## 6. 分 profile 裁剪

### 6.1 `dfir`：总控

只挂共享层入口和笔录触发，不挂深挖技能正文。

启动后只做四件事：识别题型、选择一个主剖面、列出已有材料、把缺口写成交接。它可以使用 case-fs 读题面和附件，不直接查 `.mfs`，不直接跑内存、流量或逆向。

### 6.2 `dfir-myos`：二次分析主剖面

这是本方案的重点。挂载：

- 现有二次分析规则，原样保留。
- `myos-results-analysis`：字段归一、查询顺序、换分支、嵌套 VM、哈希现算。
- `goldeneyes-forensics-report`：把已归一证据写成 GoldenEyes / MYOS 二次分析报告。
- 共享层：证据等级、缺口、审查、交接。

不挂 APK、x64dbg、账单长模板、内存全流程。需要这些时写交接，不在本剖面临时扩 scope。

### 6.3 `dfir-mem`

只挂从 memory-forensics `EXPERT.md` 抽出的同名 skill，外加共享证据模型。MCP 仍是 mem-forensics、case-fs、`17621`。memory 只记稳定坑：镜像类型、profile 选择失败时的回退、进程/网络/命令行必须有插件回执。不把某次镜像的进程列表写进长期 memory。

### 6.4 `dfir-pcap`

挂 `traffic-forensics` 与 `wmx-bill-analysis-report`。资金流水 22122 字节模板只放 references，做账单题时再读。流量和账单可以交叉，但交叉结论必须两边都有回执：流量侧有会话或文件，账单侧有对应时间、金额或对手方。单边命中只写“待交叉”，不写“已证实”。

### 6.5 `dfir-re`

挂 `apk-analysis-report`、`re-ida-static-analysis`、`re-x64dbg-dynamic-debug`，以及防御性索引。动态调试技能只保留观察点、断点意图的证据位置和交接，不写绕过、反调试对抗或恶意行为复现步骤。APK 走 jadx；原生二进制走 `8737`；文件本体走 case-fs。

### 6.6 `dfir-max`

只挂编排状态和交接。它可以看见全部 MCP，但技能层只保留“何时把题交给哪个剖面”。不把八包技能全部挂成默认技能，否则 16.8 MB 的 state 和 7091 的 SOUL 会继续膨胀，速度不会上升。

`dfir-max` 的 memory 只追加约 2 KB：八包导入后的剖面选择表、仿真边界、笔录隔离。不复制 `dfir-myos` 的表名清单。

## 7. MYOS 二次分析闭环

这是用来提高做题速度、效率和正确率的主路径。目标不是让模型更会“再跑一遍 MYOS”，而是让它会读 MYOS 已经给出的结果，只在缺口处补一次证据。

```text
题面 / 已有 MYOS 结果
        |
        v
dfir 识别题型，若主体是计算机检材且已有 MYOS 输出 -> dfir-myos
        |
        v
读 notes\device_map.computer.summary.txt
        |
        v
归一化证据模型（来源、对象、时间、动作、回执、等级、缺口）
        |
        v
按题型选一个 skill，不并行堆技能
        |
        v
只对缺口调用 MYOS MCP 补一条有界证据
        |
        v
证据等级 / 缺口 / 交接
        |
        v
记录或报告；无回执的句子标待核实
```

### 7.1 归一化证据模型

每条证据固定八个字段，名称与 hexp 等级对齐，不另起字段名：

1. `source`：MYOS 插件、表、文件、MCP 工具名。
2. `object`：用户、文件、设备、账号、IP、进程。
3. `time`：检材时间或工具时间，二者必须分开。
4. `action`：开关机、插入、发送、下载、登录、访问。
5. `receipt`：工具回执原文位置或查询语句加返回行。没有回执就没有这条证据。
6. `grade`：沿用 hexp 证据等级，不翻译成新等级。
7. `gap`：缺什么才能升级。
8. `handoff`：若缺口属于内存、流量、逆向或笔录，写给哪个 profile。

### 7.2 按题型只选一个 skill

| 题面信号 | skill | 第一跳 | 禁止 |
| --- | --- | --- | --- |
| 已有 MYOS 概览、插件库、`.mfs` | `myos-results-analysis` | summary，再按关键词选表 | 重读 70 KB 概览；全量 grep 13 GB |
| 要出 GoldenEyes 报告 | `goldeneyes-forensics-report` | 只消费已归一证据 | 边写报告边重新全量取证 |
| 开关机 | 现有规则 | `Linux_SystemInfo...BOOTSHUTDOWN` | 先去搜文档树 |
| USB | 现有规则 | `Linux_UsbInfo` | 用文件名猜测设备 |
| 微信 | 现有规则 | `Win_WeChat` | 把聊天内容当已核实事实 |
| 浏览器 | 现有规则 | `Any_Chrome` / `Any_ChromiumBrowser` | 抄历史密码结论 |
| 文档作者、修改时间 | 现有规则 | `Any_OfficeMetaInfo` | 用正文关键词代替元数据 |
| 原始盘路径 | 现有规则 | `query_device_mount_path` | 猜挂载盘符 |
| 嵌套虚拟机 | 现有规则 | 登记为新检材 | 和宿主时间线混写 |

同一分支两次零命中，停止该分支并换表，或交接。不允许第三次用更大范围重复同一查询。

### 7.3 MCP 补洞，而不是重跑

补证据时一次只发一条有界查询：

- `.mfs`：先 `sqlite_master`，确认表和列，再一条 `SELECT`，必须有 `LIMIT`。
- 命中后把行写进证据模型，不把整表贴进对话。
- 哈希只对候选文件现算 MD5。
- 浏览器密码只走 `chrome_login_decrypt.py` 的既有入口，不在技能里重写解密过程。
- didctf MCP 只用于赛题提交和核验，不把赛题口径写进笔录。
- 若 MCP 不可用，结论停在“待核实”，不允许用记忆补全。

### 7.4 收口

输出前必须过共享审查清单：

- 每句事实有回执，或已标待核实。
- 证据等级没有被口头升格。
- 缺口清单不为空时，结论段必须引用缺口。
- 交接对象只有一个主剖面。
- 笔录草稿不含赛题口径、不含未脱敏敏感信息、不含仿真步骤。
- 速度指标只在审查通过后才算有效。

## 9. 验收

导入成功必须同时满足：

| 指标 | 合格线 | 失败线 |
| --- | --- | --- |
| 首个有效工具调用 | 题型识别后直接进入对应 MCP 或既有结果，不再先通读无关技能 | 仍先大段探索目录或重读概览 |
| 重复探索 | 同一分支最多两次零命中 | 第三次仍扩大同一查询 |
| 证据覆盖率 | 结论句要么有回执，要么标待核实 | 出现无回执的肯定句 |
| 无证据断言 | 0 条新增 | 任何速度提升伴随无证据断言增加 |
| 二次分析 | 已有 MYOS 结果时，补洞查询数少于导入前的全量路径 | 仍默认重跑取证或全量 grep |
| 上下文 | 单 profile 新增 memory 2–4 KB；长模板不进 SOUL | SOUL 或启动上下文明显膨胀 |
| 隔离 | 赛题口径不进笔录；仿真步骤不进真实操作 | 任一串味 |
| 注册 | 技能按 P0 确认的方式注册，且不与 loader 重名 | 直接覆盖分类桶或 `dfir-curated` |

正确率只按有回执的结论计算。待核实不算错，但把它写成已证实算错。

## 10. 风险与控制

| 风险 | 表现 | 控制 |
| --- | --- | --- |
| 技能冲突 | 新技能和 `linux-loader`、`windows-loader` 或 curated 技能抢路由 | P0 列名；用 hexp 原名；不混入库 |
| 上下文膨胀 | `dfir-max` SOUL 继续变大，首 token 变慢 | max 只挂编排；模板进 references |
| 仿真误当真实 | 服务器包步骤被写进检材操作 | 单独边界文件；审查清单否决 |
| MCP 结果未复核 | 模型把查询结果升格为法律事实 | 无回执即待核实；等级沿用 hexp |
| 写入前未备份 | 覆盖现有 profile 或旧备份 | 新备份目录；禁止覆盖既有备份 |
| 同名双份 | 新建第二个 `myos-results-analysis` | P0 先定位，有则合并 |
| 攻击性内容渗入 | EXE 包的绕过或操作步骤进入技能 | 只导入索引和交接，实施时人工剔除 |
| 案件态污染 memory | 某次命中变成长期事实 | memory 只写稳定坑和表名 |
